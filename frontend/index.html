01 · The problem

The barrier isn't a missing Dockerfile.
It's the whole chain.

Cloning an unfamiliar repo today means writing or fixing Docker configs, orchestrating services, hunting env vars, and debugging builds by hand. Tools like docker init and buildpacks generate files, then walk away.

No Dockerfile, or an outdated one

Writing one means knowing the framework's build conventions.

→

Yoink writes one framework-level Dockerfile per service. A Next.js app and a Flask API get genuinely different recipes.

Multi-service orchestration

Monorepos need a Compose file that wires frontends, backends, and workers together.

→

Yoink is monorepo aware: deployables in apps/* and services/* become one Compose project.

Undeclared infrastructure

Code references PostgreSQL or Redis that Compose never provisions. Silent runtime failures follow.

→

Yoink sees DATABASE_URL in your source and adds Postgres with a healthcheck and a wired connection string.

Scattered environment variables

Config lives across dozens of files with no consolidated template.

→

Every process.env, os.getenv, VITE_, and NEXT_PUBLIC_ reference lands in a per-service .env.example.

Build failures demand Docker fluency

One bad layer and a newcomer is stuck reading compiler spew.

→

Failing builds go to the LLM heal loop, which applies a fix and retries, capped at three attempts.

Tools generate files and walk away

Scaffolding isn't a running application.

→

Yoink builds, verifies against your Docker daemon, and hands off a healthy stack with a live dashboard.

02 · How it works

Eight steps. One command.

Every yoink init runs the same auditable pipeline: deterministic first, LLM second, verification always.

  1. 01

    Clone

    HTTPS, SSH, branch, or sub-directory URLs. PATs travel through git's header, never the command line.

  2. 02

    Map the tree

    Walks the repo, skipping node_modules, .venv, build output, and monorepo noise.

  3. 03

    Detect services

    14 framework profiles across Node and Python, each with a confidence rating.

  4. 04

    Extract env vars

    Source-level references become a per-service .env.example template.

  5. 05

    Infer infrastructure

    Env hints and dependency lists add backing services with healthchecks and volumes.

  6. 06

    Generate

    One Dockerfile per service plus a single docker-compose.yml with port-collision avoidance.

  7. 07

    Write outputs

    Everything lands in yoink-outputs/ with a .gitignore that keeps real secrets out.

  8. 08

    Build & heal

    Builds against your Docker daemon. On failure, the LLM patches the config and retries, up to 3 times.

03 · Features

Generate, run, heal.
Then drive it daily.

Most generators stop at files. Yoink stays for the build, the failure, the fix, and every restart after that.

Self-healing builds

When a build fails, Yoink captures the failing service and the last 80 lines of output, sends them along with the Dockerfile and Compose to your configured LLM, applies the returned fix, and retries. Bounded by --heal-tries, default 3. If it can't converge you get a readable failure summary, not an infinite loop.

✗ service "api" failed to build → sent Dockerfile + compose + last 80 lines to the LLM → patch applied (attempt 1/3) ✓ Build succeeded

Infrastructure inference

Env-var references and dependency manifests are scanned for infrastructure hints. Each match adds a Compose service with a healthcheck, a named volume, and a depends_on: service_healthy edge.

DATABASE_URL → postgres:16-alpine REDIS_URL → redis:7-alpine MONGO_URI → mongo:7 + MySQL · RabbitMQ · Elasticsearch

Framework-aware generation

Multi-stage builds for Next.js and NestJS, nginx for static SPAs, slim images for Python. Package managers such as npm, yarn, pnpm, pip, and poetry are picked from lockfiles, and ports are read from entry files.

nextnestfastifyexpressvitefastapidjangoflask+6 more

Monorepo-native

Compose build context sits at the repo root, so each Dockerfile copies from its own sub-directory. Workspace-root package.json files and libraries without start scripts are skipped automatically.

COPY apps/web/package*.json ./ RUN npm ci && npm run build

It remembers you

Env values, port choices, and detection state persist per repo. Your second yoink up needs zero input.

~/.yoink/state/fastapi-template/ ├── yoink.lock ├── env-overrides.json └── settings.json

Any LLM, or none at all

Pick a provider once in yoink setup; the choice persists. Prefer zero cloud calls? Run Ollama locally for a fully offline mode, or pass --no-agent for pure static analysis with no API key and no LLM round-trips.

05 · Install

Up and running
in under a minute.

A single binary you build once. Go 1.21+ and git are needed to compile; Docker Engine and Compose v2 are only needed when you run stacks (--no-build skips them).

curl -fsSL https://raw.githubusercontent.com/monojitgoswami69/yoink/main/install.sh | bash

Installs to ~/.local/bin. Windows builds from source with go build -o yoink.exe . Platform-by-platform steps, the Makefile route, and verification live in the installation guide.
